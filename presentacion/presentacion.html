El mundo antes de DHCP

En los años 90, los administradores de sistemas configuraban las redes puesto por puesto.

  • Había que introducir a mano: Dirección IP, Máscara, Puerta de Enlace y DNS.
  • Se llevaban registros en hojas de cálculo o libretas para saber qué IP tenía cada PC.

El problema del error humano

La configuración manual traía graves dolores de cabeza:

  • IPs duplicadas: Dos equipos con la misma IP causaban un conflicto y ninguno tenía red.
  • Errores tipográficos: Un número mal en la máscara aislaba al equipo.
  • Pérdida inmensa de tiempo (horas de trabajo para un administrador).

La explosión móvil

Hoy en día, el paradigma manual es imposible.

  • Tenemos smartphones, portátiles, tablets, IoT.
  • Los dispositivos entran y salen de la red constantemente.
  • El usuario espera conectarse al Wi-Fi y tener internet al instante.

¿Qué es DHCP?

Dynamic Host Configuration Protocol

  • Protocolo de red que asigna automáticamente parámetros de configuración a los dispositivos.
  • Convierte la red en una experiencia verdaderamente Plug & Play.
  • Definido en el RFC 2131.

Arquitectura Cliente/Servidor

  • Servidor DHCP: El administrador de la red. Posee un "banco" de IPs libres y las reglas de configuración.
  • Cliente DHCP: Cualquier equipo (PC, móvil, impresora) configurado para "Obtener una IP automáticamente".

Transporte: Protocolo UDP

DHCP utiliza UDP (User Datagram Protocol) en la capa de transporte.

  • Es rápido y de baja latencia.
  • No orientado a conexión: No hay un "handshake" previo como en TCP, lo cual es vital porque el cliente aún no tiene IP.

Puertos estandarizados

Para que la comunicación fluya, cliente y servidor usan puertas distintas:

  • Puerto UDP 67: El servidor DHCP está siempre a la escucha en este puerto.
  • Puerto UDP 68: El cliente escucha aquí las respuestas del servidor.

Comunicación inicial: Broadcast

¿Cómo hablas con alguien si no sabes quién es ni dónde está?

  • Al iniciar, el cliente no tiene IP y no sabe la IP del servidor.
  • Solución: Hablar a gritos. Envía paquetes a la dirección de Broadcast (255.255.255.255 o MAC FF:FF:FF:FF:FF:FF).

El núcleo del protocolo:
El Proceso D.O.R.A.

Discover • Offer • Request • Acknowledge

1. Discover (Descubrir)

  • De: Cliente (IP Origen: 0.0.0.0)
  • Para: Broadcast (Destino: 255.255.255.255)
  • Traducción: "¡Hola a todos! Acabo de conectarme a esta red, ¿hay algún servidor DHCP que pueda asignarme una IP?"

2. Offer (Ofrecer)

  • De: Servidor DHCP
  • Para: Cliente (Unicast o Broadcast)
  • Traducción: "¡Hola! Te he escuchado. Tengo libre la IP 192.168.1.50. Te la guardo un momento por si la quieres."

3. Request (Solicitar)

  • De: Cliente
  • Para: Broadcast (Avisa a todos)
  • Traducción: "¡Acepto la IP 192.168.1.50 del Servidor X! El resto de servidores ya pueden liberar las IPs que me hubieran ofrecido."

4. Acknowledge (Confirmar)

  • De: Servidor DHCP
  • Para: Cliente
  • Traducción: "Trato hecho. La IP es tuya oficialmente. Aquí tienes también el DNS y el Router para que navegues."

El "Alquiler" (Lease)

El DHCP no regala las IPs para siempre, las presta o alquila por un tiempo determinado.

  • Si un equipo se desconecta para siempre y la IP fuera fija, el servidor acabaría quedándose sin direcciones.
  • Gracias al alquiler, las IPs de los equipos inactivos vuelven a estar disponibles.

Estrategias de Tiempo

El administrador decide el tiempo según el entorno:

  • Cafeterías/Aeropuertos: Tiempo muy corto (1 - 2 horas). Alta rotación de clientes.
  • Oficinas corporativas: Tiempo medio/largo (8 días). Los equipos son los mismos todos los días.

Temporizador T1 (Renovación)

¿Cuándo pide el cliente renovar el alquiler?

  • Ocurre automáticamente al 50% del tiempo de concesión.
  • El cliente envía un paquete DHCP Request al servidor original (esta vez por Unicast, directo).
  • Si el servidor responde, el contador de tiempo vuelve a 0.

Temporizador T2 (Reenganche)

¿Qué pasa si el servidor original estaba apagado en el 50%?

  • El cliente sigue usando la IP y espera hasta el 87.5% del tiempo total.
  • Aquí entra en pánico y envía un Broadcast buscando cualquier servidor DHCP de la red que quiera renovarle el alquiler.

Expiración Total

Si se llega al 100% del tiempo y ningún servidor ha respondido:

  • El cliente tiene la obligación de soltar la IP.
  • Desconecta sus servicios de red.
  • Vuelve al paso 1: empieza a gritar mensajes DHCP Discover constantemente hasta que alguien responda.

Un apunte: Hardware vs Lógica

Para configurar un servidor, debemos entender que vinculamos dos mundos:

  • MAC Address: Dirección física de la tarjeta de red del cliente. Inmutable.
  • IP Address: Dirección lógica que le entregará nuestro servidor DHCP.

Piezas del Servidor: El Ámbito

El Ámbito (Scope) es la agrupación administrativa básica.

  • Define la red física o lógica completa en la que el servidor va a trabajar.
  • Generalmente, equivale a una subred (ej: 192.168.10.0 /24).
  • Sin ámbito, el servidor está ciego y no hace nada.

El Rango de Direcciones

Dentro del ámbito, definimos el tramo exacto que se va a repartir.

  • Ejemplo de ámbito: 192.168.1.0 a 192.168.1.255
  • Rango asignado: Podríamos decidir repartir solo desde la .100 hasta la .200.

Las Exclusiones

A veces un rango incluye IPs que ya tienen dueño.

  • Son direcciones prohibidas para el servidor DHCP.
  • ¿Por qué? Porque un servidor físico, un switch o una impresora tienen esa IP configurada de forma estática manualmente y no queremos conflictos.

Reservas (MAC Binding)

Excepciones a la regla de la "dirección dinámica".

  • Le decimos al DHCP: "Cuando veas la tarjeta de red con MAC AA:BB:CC..., no le des una IP aleatoria, dale siempre la 192.168.1.50".
  • Muy útil para servidores o impresoras que necesiten una IP fija pero centralizando su gestión en el DHCP.

El Pool (Piscina)

Concepto final del agrupamiento de IPs.

  • El Pool es lo que queda matemáticamente: Rango Total - Exclusiones - Reservas.
  • Es el saco real de direcciones que están libres y listas para ser entregadas a los móviles y PCs de los usuarios.

Opciones DHCP (RFC 2132)

Dar solo una IP a un PC es dejar el trabajo a medias (no podría salir a Internet).

  • El servidor envía "Opciones", metadatos extra que configuran la red a fondo.
  • Existen decenas de opciones estándar numeradas.

Opción 1: Máscara de Subred

La opción más crítica de todas junto a la IP.

  • Le dice al cliente cómo de grande es la red.
  • Ejemplo: 255.255.255.0.
  • Sin esta opción, el cliente no sabe quién está en su red local y quién está fuera.

Opción 3: Router (Puerta de Enlace)

El camino hacia Internet.

  • Indica la IP del router por el que debe salir el tráfico hacia redes externas.
  • Normalmente es la primera (.1) o la última (.254) IP de la subred.

Opción 6: Servidores DNS

La traducción de nombres.

  • Asigna los servidores que traducen dominios (como google.com) a IPs reales.
  • Se pueden mandar varios (Primario y Secundario) por si uno falla.

Opciones 66 y 67 (Arranque PXE)

Magia avanzada de sistemas.

  • Permiten que un equipo sin sistema operativo arranque e instale Windows o Linux a través de la red.
  • Opción 66: IP del servidor TFTP.
  • Opción 67: Nombre del archivo de arranque.

¿Y si el Servidor muere? -> APIPA

Automatic Private IP Addressing

  • Si el cliente enciende, grita 'Discover' y nadie responde tras varios intentos, el SO toma el control.
  • Para no quedarse totalmente inutilizado, se auto-asigna una dirección de emergencia.

El famoso rango 169.254.x.x

El síntoma clásico de problemas de red.

  • Cualquier IP que empiece por 169.254... significa APIPA.
  • Permite hablar con otros PCs de la misma sala que también estén en APIPA (red local de rescate).
  • NO permite salir a Internet (no hay Puerta de Enlace).

El problema de las redes grandes (VLANs)

En redes corporativas hay múltiples departamentos (VLANs).

  • Regla sagrada: Los routers bloquean el tráfico Broadcast de una VLAN a otra.
  • Si un usuario (VLAN 10) grita 'Discover', el Servidor DHCP central (VLAN 99) nunca le escuchará.

La Solución: DHCP Relay Agent

También conocido como IP Helper.

  • Se configura en el router principal.
  • El router escucha el Broadcast local, envuelve la petición y se la manda directamente al Servidor por Unicast cruzando las VLANs.

Implementación: GNU/Linux

Históricamente liderado por isc-dhcp-server (y ahora Kea). Todo por comandos.

subnet 10.0.0.0 netmask 255.255.255.0 {
  range 10.0.0.50 10.0.0.100;
  option routers 10.0.0.1;
  option domain-name-servers 8.8.8.8, 1.1.1.1;
  default-lease-time 600;
  max-lease-time 7200;
}

La sintaxis es implacable: falta un punto y coma (;) y la red entera cae.

Implementación: Windows Server

  • Se instala como un "Rol" del servidor.
  • Gestión completamente gráfica mediante la consola MMC.
  • Se integra perfectamente con Active Directory y actualiza el DNS automáticamente cuando un PC recibe IP.

Seguridad: "Rogue DHCP"

El peligro de los servidores falsos.

  • Cualquiera puede conectar un router doméstico a la red del instituto/empresa.
  • Ese router empezará a repartir IPs (Offer) más rápido que el servidor legítimo.
  • Resultado: Un ataque Man-in-the-Middle. Se intercepta todo el tráfico.
  • Mitigación: Función DHCP Snooping en los switches corporativos.

Conclusión

  • DHCP es el servicio invisible que mantiene vivas las redes modernas.
  • Dominar los ámbitos, el proceso DORA y el Relay Agent es fundamental para cualquier técnico ASIR.
