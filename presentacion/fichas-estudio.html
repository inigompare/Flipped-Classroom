Fichas de Estudio:
Servicio DHCP

¿Por qué existe el DHCP?

El Pasado: Configuración Manual

En las redes antiguas, el administrador introducía IP, Máscara, Puerta de Enlace y DNS equipo por equipo a mano.

  • Generaba conflictos de IP (dos equipos con la misma IP).
  • Imposible de escalar con la llegada de portátiles y móviles.

La Solución: Plug & Play

DHCP convierte la red en dinámica. Un dispositivo se conecta y recibe toda la configuración al instante.

  • Gestión centralizada desde un único servidor.
  • Las IPs "vuelven a la piscina" y se reutilizan cuando los equipos se van.

Fundamentos y Protocolo

Entendiendo la arquitectura y el modelo de comunicación

Arquitectura Cliente-Servidor

Transporte y Puertos

DHCP utiliza el protocolo de transporte UDP por su velocidad y naturaleza no orientada a conexión (vital cuando no hay IP aún).

  • Puerto UDP 67: Donde escucha el Servidor.
  • Puerto UDP 68: Donde escucha el Cliente.

Broadcast inicial

Un cliente recién conectado sufre de "amnesia de red". No tiene IP ni sabe dónde está el servidor.

Por ello, inicia la comunicación enviando paquetes de Broadcast (255.255.255.255), gritando a toda la red local para localizar ayuda.

El Ciclo D.O.R.A.

Discover

El cliente emite un Broadcast a la red diciendo: "¡Hola! No tengo IP, ¿hay algún servidor DHCP por aquí?"

Offer

El servidor responde ofreciendo una concesión: "Sí, estoy aquí. Te ofrezco usar temporalmente la IP 192.168.1.50."

Req. & Ack.

El cliente hace un Request aceptando la oferta, y el servidor envía el Ack final validando la transacción.

La dirección IP no se regala, se alquila por un tiempo determinado.
El concepto del "Lease Time" (Tiempo de concesión)

Tiempos de Renovación

50%
Temporizador T1

Renovación Unicast

Al transcurrir exactamente la mitad del tiempo de concesión, el cliente intentará renovar amablemente su alquiler contactando directamente al servidor original mediante Unicast.

Si el servidor original ha muerto, al llegar al 87.5% (T2) el cliente enviará un Broadcast desesperado buscando cualquier otro servidor de rescate.

Componentes y Configuración

Las piezas que conforman un Servidor DHCP funcional

Anatomía del Servidor

Ámbito y Rango

El Ámbito (Scope) define la subred lógica entera. El Rango es el tramo exacto de direcciones listas para repartir.

Exclusiones

Direcciones dentro del rango prohibidas para el servidor, normalmente porque están fijadas estáticamente en routers o impresoras.

Reservas

Asignación estática basada en DHCP. Se vincula una dirección MAC específica a una IP para que un equipo siempre obtenga la misma.

Implementación: OS Server

Windows Server

Se instala como un Rol de Servidor y se gestiona mediante una cómoda interfaz gráfica (consola MMC).

  • Integración nativa con Active Directory.
  • Requiere ser "Autorizado" en el dominio para funcionar (mecanismo anti Rogue DHCP).

GNU/Linux

Históricamente isc-dhcp, hoy Kea DHCP. Configuración basada enteramente en ficheros de texto.

  • Se configura editando texto (ej: /etc/dhcp/dhcpd.conf).
  • Sintaxis estricta: olvidar un punto y coma (;) tumba el servicio.

Opciones DHCP (RFC 2132)

Código Nombre de la Opción Descripción en ASIR
Opción 1 Subnet Mask (Máscara) Obligatoria. Define el tamaño y los límites de la red local del cliente.
Opción 3 Router (Puerta de Enlace) Dirección IP del router por el cual el cliente podrá salir a Internet.
Opción 6 Domain Name Server (DNS) Servidores encargados de traducir nombres de dominio en direcciones IP.
Opción 66/67 TFTP Server Name / Bootfile Opciones avanzadas utilizadas para el arranque PXE (instalar SO por red).

Arranque por Red (PXE)

Magia ASIR: Bootear sin Disco

Gracias a las Opciones 66 y 67 de DHCP, un PC "vacío" (sin sistema operativo ni disco duro) puede encenderse y descargar un SO completo a través del cable de red.

El DHCP le dice al PC: "Tu servidor de instalación (TFTP) es la IP X y debes descargar el archivo de arranque Y".

El Peligro de APIPA

IP: 169.254.x.x

Si el cliente envía un Discover pero el servidor DHCP está caído (o el cable defectuoso), el sistema operativo entra en modo emergencia.

Se auto-asigna una dirección APIPA (Automatic Private IP Addressing). Con esto se logra conexión con otros equipos locales en la misma situación, pero no permite conexión a Internet al carecer de Puerta de Enlace.

Tip ASIR: Si ves esta IP en un ipconfig, el problema está en la red, no en el PC.

Comandos de Diagnóstico

Comando Sistema Función ASIR
ipconfig /release Windows (Cliente) Suelta la IP actual y se la devuelve al servidor DHCP.
ipconfig /renew Windows (Cliente) Obliga a la tarjeta a iniciar el proceso D.O.R.A. para pedir red.
dhclient -r / dhclient GNU/Linux (Cliente) Equivalente a release (-r) y renew para soltar/pedir IP.
systemctl status kea GNU/Linux (Servidor) Comprueba si el servicio DHCP está corriendo o falló por sintaxis.

Seguridad y Entornos Complejos

  • Ataque Rogue DHCP: Si un alumno conecta un router doméstico a la red, este actuará como DHCP falso, repartiendo IPs inválidas, interceptando el tráfico y hundiendo la red del centro.
  • Mitigación (DHCP Snooping): Los switches corporativos deben configurarse para que solo admitan paquetes Offer desde el puerto legítimo donde conectamos nuestro servidor.
  • Redes con VLANs (DHCP Relay): Los routers bloquean los Broadcast. Si hay VLANs, se debe usar un DHCP Relay Agent (IP Helper) en el router para que envíe el Broadcast del cliente como Unicast directo al servidor.
